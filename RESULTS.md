# Peregrine v0.2 — the full benchmark, our language included

Date: 2026-11-09 (rebuilt from scratch this session). Machine: 2-core
Intel Xeon cloud VM, 4.1 GB RAM, Debian 13; gcc 14.2.0, g++ 14.2.0,
rustc 1.99.1, Go 1.22.10, CPython 3.12, Goose rebuilt from its own source
(this repo, g++ -O2 -std=c++20). Method: whole-process wall time, best of
3 timed reps after 1 warmup for compiled languages; **pure CPython gets no
warmup and a single rep** (disclosed: it is 1-3 orders of magnitude
slower; warming the cache does not change that). Peak RSS via wait4.

**Every implementation of every benchmark prints bit-identical checksums,
verified by the harness before any timing counts** — 33 implementations
across 5 workloads (Peregrine, Goose, C, C++, Rust, Go, Python; the
sortrec limitation row omits Go/Python). The Python sources were also
cross-checked bit-exactly against C at a reduced N.

## Where the wins come from

- **mix (3.5x vs C, C++, Goose, Go; 3.0x vs Rust).** The u32
  multiply-shift chain cannot vectorize at the x86-64 SSE2 baseline, so
  gcc -O2 (for C, C++ and Goose's output), rustc -O and Go's compiler all
  stay scalar — verified in the disassembly, zero vector multiplies in
  any of them. Peregrine proves the loop trap-free and dependence-free,
  emits `#pragma omp simd` with reduction clauses, and runs 16-wide
  AVX-512. The identical round table in every language is generated by
  `gen_mix.py`, so the kernels cannot diverge.
- **sort (3.7x vs std::sort, 4.4x vs Go's slices.Sort, 6.0x vs qsort).**
  `sort()` lowers to a 2-pass 16-bit radix sort: linear passes, no
  comparator calls, no function pointers. Honest miss: Rust's
  `sort_unstable` (pdqsort) is an excellent sort; we beat it by 1.64x,
  not 3x.
- **records (3.2x vs idiomatic C++, 3.6x vs Go, 2.8x vs Rust).** Proven
  widths + variant-segregated stores + in-place strings against
  `std::variant`/`enum + String`/interface+type-switch heap layouts. This
  is the workload family Goose itself claims, and the same checksums as
  the original study: today the rebuilt Goose binary measures 1.08 s to
  our 0.63 s (1.70x; earlier sessions measured 1.46 s for the same
  binary — cross-session VM drift, which is why only same-session ratios
  are quoted).

## Where Peregrine does not win, and why

- **map: Goose wins (0.62x).** Counting 16M occurrences of 64K keys is a
  random-probe workload — one hash-table probe per op into a 4 MB table,
  DRAM/L3-latency-bound for every implementation. Goose's dictionary
  (slice keys, open addressing, no per-op allocation) is genuinely good,
  and its slice-keyed design forces the key material into a separate
  pass, leaving its hot loop with nothing but probe+increment. Our bump
  builds the key in place per op and pays the same probe. We beat the
  node-based and SipHash-hashed containers (C++ 1.67x, Rust 1.43x,
  Go 1.72x) and lose to the one rival whose map has no per-op work left
  to remove. This row is the honest boundary of the claim.
- **sortrec: our payload sort loses to pdqsort (0.82x vs Rust).** A naive
  16-bit-digit radix scatter of 16-byte records thrashes 64K write
  streams. Documented as a SPEC limitation; fixing it is radix
  engineering (prefetch, smaller digits), not language design. Kept in
  the table because a row set with only wins is an advertisement.
- **records vs Rust: 2.81x, a hair under 3x** on this run (2.9-3.4x
  across earlier same-session runs; the VM drifts ±15%).

## Reproducing

- `benchmarks/` — every source in all seven languages; `gen_mix.py`
  generates the mix round table for all of them from one definition.
- `benchmarks/build_suite.sh` — builds all 33 binaries and prints every
  checksum; `benchmarks/run_suite.py` — the checksum-gated timing harness;
  `benchmarks/compile_speed.py` — the compile table.
- Toolchains used: gcc/g++ 14.2, rustc 1.99.1, Go 1.22.10, CPython 3.12,
  Goose rebuilt from source with its vendored TinyCC.

## What the language is

~1,800 lines of auditable Python (front.py, backend.py) emitting C.
See SPEC.md for the language: proven range widths, variant-segregated
stores, in-place string plans, buf/map/sort, proven-safe auto-SIMD,
no UB, traps that name their line.
